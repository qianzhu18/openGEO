# 本地优先与浏览器采集：OpenGEO 该怎么复刻 Topify

日期：2026-11-02。回答三件事：能不能完全照搬 Topify、本地能不能直接用浏览器、OpenGEO 的意义到底在哪。

## 0. 产品边界（2026-11-02 定稿）

**只做个人开源版，不做商业化版本。**

- 本仓库服务个人：自己的电脑、自己的浏览器登录态、自己的 API Key、自己的文件。
- 企业 / 团队 / 多租户 / 云端采样 / 计费 / 权限不做；这类需求由 Topify 结构的云端产品承接。
- 不追求"像 SaaS"：没有 credits、席位、发票、账号池。
- 判断标准：这个改动是否让个人用户更快拿到可信结论、是否让证据更可回放。见 [AGENTS.md](../AGENTS.md)。

## 1. 结论

**可以照搬 Topify 的“流程、数据模型、指标、动作”，但不该照搬它的“云端多租户运营形态”。**

本地浏览器采集不是 P2，而是 OpenGEO 的核心差异化，应该提到 P0/P1。

一句话定位：

> 把你的电脑变成 GEO 工作台：用你自己的账号、你自己的地区、你自己的文件，跑可审计的 AI 可见性测量。

## 2. 为什么“照搬框架”是对的一半

Topify 真正值钱的是这四样，和云端无关：

| 可照搬 | 对应我们的实现 |
| --- | --- |
| 信息架构：Agent / Analyze / Tracking / Optimization / Preferences / Management | 已经按这套 IA 做了工作台 |
| 数据模型：Project → Prompt → Observation → Citation → Action → Publication | 已有雏形，缺统一与调度 |
| 指标口径：Visibility / Sentiment / Position / SOV / Source Used | 已有 `brand-metrics.ts`，需补引用聚合 |
| 动作闭环：动作 → 草稿 → 审批 → 发布 → 复测 | 有草稿与任务，缺审批与复测 |

不能照搬的是**它为什么这么设计**：

- credits 计费：因为云端每天替你跑几十个 prompt、几十个引擎，模型/浏览器/代理都要钱；
- 团队/席位/API Key：因为它是 SaaS；
- 每日全量：因为要卖给 agency 做交付；
- 云端浏览器农场：因为要规模化、要地区、要账号池。

这些对“本地单用户”是过度设计。**本地用户已经为 ChatGPT Plus / Gemini 付过费了，边际采样成本接近 0——这才是开源本地版的经济基础。**

## 3. 本地浏览器：能做，而且必须做

### 3.1 三种采集模式

| 模式 | 真实度 | 成本 | 稳定性 | 合规/风险 | 适合 |
| --- | --- | --- | --- | --- | --- |
| API（OpenRouter/OpenAI/Claude） | 中：与网页答案不同 | 按 token 付费 | 高 | 低 | 基线、批量、CI |
| **本地浏览器（用你的登录态）** | **高：用户所见** | **接近 0**（已付订阅） | 中：UI 变、验证码 | 中：平台 ToS、账号风险 | **个人真实 GEO** |
| 云端浏览器农场 | 高 | 高（机器+代理+账号） | 高 | 高 | agency/规模化 |

Our 目标不是替代 API，而是**两种都支持、明确标注**：

```text
API 采集   → 快速、便宜、可批量，标注“API 结果”
浏览器采集 → 真实、用你自己的账号，标注“网页结果 + 账号/地区/时间”
```

### 3.2 已经验证到的程度

- 用专用 Chrome profile（`launchPersistentContext`）打开公开页面：正常，可读 DOM；
- 全新 headless profile 打开 ChatGPT：被 Cloudflare 拦成 "Just a moment..."；
- 结论：**本地浏览器可行，但不能“无脑 headless”**。需要：
  - 专用 persistent profile（不要碰用户日常 Chrome）；
  - 首次由用户在有头窗口里登录一次；
  - 之后复用该 profile（有头或 headless-with-session），并对验证码做人工接管；
  - 或者让用户用 `--remote-debugging-port` 启动自己的 Chrome，我们 attach。

### 3.3 为什么不用“复制用户 Chrome profile”

macOS 上 Chrome 的 Cookie 受 Keychain 加密，复制 profile 目录经常拿不到登录态；直接复用用户的日常 profile 又会在自动化时干扰用户、且容易触发风控。**专用 profile + 首次登录**是更稳的工程选择。

## 4. 推荐架构：本地采集三层

```text
browser/
  bridge.ts       连接方式：attach CDP / 启动专用 profile / 扩展（后续）
  session.ts      每个引擎一个会话：登录态、地区、语言、UA、限速
  engines/
    chatgpt.ts    打开 → 输入问题 → 等回答 → 提取正文/引用/时间
    gemini.ts
    perplexity.ts
    aio.ts        Google AI Overview（更依赖页面结构）
  evidence.ts     保存：DOM 快照、截图、最终 URL、回答文本、引用、耗时
collector/
  scheduler.ts    本机 cron：机器在线才跑；预算（次数/时长）；幂等键
  runner.ts       run → job(问题×引擎) → attempt；失败重试不进分母
judge/
  normalize.ts    品牌别名/域名/歧义
  metrics.ts      mention/position/sentiment/SOV/citations
workspace/
  SQLite + 本地 UI + 证据查看器
```

关键工程点：

1. **协议落盘**：引擎、模式（UI/API）、账号标识（本地哈希）、地区、语言、时间、模型选择、页面版本；
2. **证据三件套**：回答文本 + DOM 快照 + 截图；没有截图就不能声称“用户所见”；
3. **限速与中断**：每引擎每小时上限、随机间隔、失败退避；用户一操作就暂停；
4. **人工接管**：验证码/2FA 时弹出有头窗口，用户处理完继续；
5. **可回放**：同一条回答能重开证据，指标能从原文重算。

## 5. 复刻映射：Topify 能力 → 本地实现

| Topify | OpenGEO 本地版 |
| --- | --- |
| credits 计费 | 本地预算：每日/每次运行的请求数、时长、token 上限；不卖 credits |
| 每日云端全量采样 | 本机 cron，机器在线才跑；默认 1–3 个问题/天 |
| 云端浏览器 + 账号池 | 你自己的 Chrome 专用 profile / attach |
| 团队、席位、API Key | 单用户；本地 API token 可选 |
| Semrush 关键词量 | 可选接入；没有就标 UNKNOWN，不编数字 |
| WordPress/Shopify/Framer 发布 | 本地 CMS adapter + 人工发布登记 |
| Webhook | 本地事件日志 + 可选 webhook |
| 多项目 | 本地多 workspace，但默认单品牌 |

## 6. 风险与边界（必须写进产品）

| 风险 | 现实 | 应对 |
| --- | --- | --- |
| 平台 ToS | 自动化访问消费级产品可能违反条款 | 只服务个人自查、限速、明示风险；不提供批量养号 |
| Cloudflare/验证码 | headless 新 profile 直接被拦 | 专用 profile + 首次人工登录 + 人工接管 |
| UI 改版 | 选择器失效 | 用可访问性树/文本定位，加健康检查与降级 |
| 非确定性 | 同问题不同时间答案不同 | 记录协议、重复采样、不承诺稳定排名 |
| 机器离线 | 笔记本合盖就停 | 本地队列 + 补跑；VPS 可选 |
| 单机并发 | 一个浏览器同时只能跑少量会话 | 串行/小并发，按引擎限流 |
| 隐私 | 登录态与项目数据在本机 | 不上传、不采集无关页面、可一键清除 |

## 7. 两周计划（建议）

| 天 | 交付 | 验收 |
| --- | --- | --- |
| 1–2 | `browser/session.ts`：专用 profile 启动/复用；登录状态检测 | 能打开 ChatGPT/Gemini/Perplexity 并判断是否已登录 |
| 3–5 | 单引擎 adapter（先 ChatGPT 或 Perplexity）：提交问题、提取回答与引用 | 一条问题 → 文本 + 引用 + 截图落盘 |
| 6–8 | `evidence.ts` + 证据查看器：回答、引用、截图、协议 | 报告能点回截图与原文 |
| 9–10 | 本地 scheduler：1 问题 × 1 引擎 × 每天；预算与失败重试 | 连续 3 天自动跑，重启恢复 |
| 11–12 | UI：`Use my browser` 开关、引擎登录状态、运行进度 | 用户不写代码即可跑 |
| 13–14 | 文档：ToS/风险、UI vs API 披露、失败处理 | 外部用户能独立完成一次 |

## 8. 意义：为什么这是 OpenGEO 而不是“又一个 Topify”

- **资源主权**：用你已有的订阅、你的地区、你的登录态，边际成本接近 0；
- **数据主权**：回答、引用、截图、项目数据都在本机，不上传；
- **可审计**：协议、分母、失败样本、截图全部可查，可 replay；
- **可扩展**：CLI / MCP / 本地模型（Ollama）/ 本地文件，都能接进来；
- **诚实**：UI 与 API 分开标注，不把 API 结果说成网页结果。

**Topify 卖的是“替你在云端跑”；OpenGEO 卖的是“把你的电脑变成能跑的机器，并且你能看懂它跑得对不对”。**

## 9. 已定：个人开源版

方向已经确定（2026-11-02）：只做个人开源版，不做商业化版本；企业功能交给 Topify 结构的云端产品。

因此本地浏览器采集是主线，不是可选项。使用前提只有一次：在专用 profile 的有头窗口里登录一次 ChatGPT（后续可加 Gemini / Perplexity），之后 OpenGEO 复用该会话。

## 11. 账号政策与登录（2026-11-03）

- 专用 profile 绑定**唯一指定的 Google 账号**；非 Claude 引擎一律用该账号 SSO 登录（Claude 不支持 Google SSO，暂不纳入浏览器采集）。
- 登录入口：`cd code && npm run browser:login`（默认 Perplexity，可传 `chatgpt`）；命令会打开有头窗口并等待会话 Cookie 出现（最长 5 分钟）。
- 不加第二个账号、不重建 profile 绕过配额或风控。

## 10. 现在的实现状态（2026-11-02）

已经落地的最小闭环：

| 模块 | 作用 |
| --- | --- |
| `code/src/citekeel/browser/session.ts` | 启动/复用专用 Chrome profile；也可 attach 到 `--remote-debugging-port=9222` |
| `code/src/citekeel/browser/engines/chatgpt.ts` | 检测登录态；提交问题；等待回答结束；提取正文与引用 |
| `code/src/citekeel/browser/evidence.ts` | 保存 `answer.txt`、`page.html`、`screenshot.png`、`evidence.json` |
| `code/src/citekeel/browser/cli.ts` | `browser:probe` / `browser:check` / `browser:ask` |

命令：

```bash
cd code
npm run browser:probe            # 验证浏览器能启动、能读页面
npm run browser:check            # 打开有头窗口，检查/引导登录 ChatGPT
npm run browser:ask -- "What is GEO?"
```

验证结果：

- `browser:probe` 打开 `example.com` 正常，标题与正文可读；
- 未登录的新 profile 打开 ChatGPT 会命中 Cloudflare，`check` 返回 `unknown` 并提示人工登录；
- 登录后需要再跑一次 `check`，确认变为 `signed_in`，再执行 `ask`。

限制：

- 默认**有头**运行（`OPENGEO_BROWSER_HEADLESS=0`）；headless 容易被 Cloudflare 拦，只适合公开静态页；
- ChatGPT UI 随时可能改版，选择器需要维护；
- 验证码/2FA 必须人工接管，不绕过；
- 证据保存在 `code/data/evidence/<id>/`，默认不上传。

下一步：登录一次跑通 `browser:ask`，再把这条链路接进工作台（“Use my browser”开关 + 结果页显示截图与引用）。
