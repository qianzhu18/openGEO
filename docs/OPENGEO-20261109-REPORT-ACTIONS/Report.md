# 0.4.0 诊断报告与行动中心

## 交付

两个功能分支合入 `codex/opengeo-v0-4`。报告分支 `0c20153`，行动中心分支 `be21b7f`。Topify 研究见 [竞品记录](../../references/competitors/topify/13-行动中心与报告-2026-11-09.md)。Topify 有内容建议和 Generate 入口；本轮没有调用其生成或应用补丁。

默认报告采用「诊断结论 → 关键发现与解释 → 优先行动/制作单 → 问题覆盖 → 信源诊断 → 失败摘要 → 摘录 → 复测范围」。Markdown 与 HTML 同一投影；完整证据改由 `/api/runs/:id/report-evidence` 单独下载，JSON 包含原始建议、状态覆盖和诊断投影。HTML 继续禁脚本、远程图片与非 HTTP(S) 链接。完整证据保留旧结构用于复核。

`diagnoseRun` 只读已保存数据，不调用模型。无数据不出品牌建议；污染 run 不出行动。旧任务全部关联样本必须有效且符合筛选才复用，防止跨模型借用旧计数。事实任务关联声明必须存在；新制作单使用题目里的具体条件、原文 ID、事实缺口和验收。候选比较不当成自然发现，未独立审计官网就不认定缺内容。规则制作单不是已经验证的运营策略。

中英文共用行动中心：类别概览卡、状态/类别/优先级过滤、卡片、折叠制作单与原文、加入待办、完成、跳过和恢复。状态保存在当前 run 的 `actionStates`，原 `actions`、原始回答和协议保留。状态刷新后可恢复；未引入团队工作区。采集异常在折叠执行记录中，不混作品牌内容建议。完成状态条收紧，运行中继续前置进度并隐藏结果。

## 验证与实际数据

`npm run build`、`npm test`（120/120）、`npm run test:browser`（26/26）通过。浏览器覆盖中英文入口、筛选无结果、原文展开、待办/完成/跳过/恢复与刷新、375px 无横向溢出、报告下载与安全渲染。真实数据另只读导出并检查版面，不新增模型请求。

用户提供 run `cba64511-2d9c-42f4-accb-ca0954f19405`：10 题都有至少一条有效回答，18/50 单元有效、32 缺失。新版明确只形成分组线索，不能代表所有计划平台。原报告约 259KB、2755 行；新版 18,597 字节、266 行，完整证据仍独立保留。点名核验不能证明自然推荐，候选集合题也不能算自然品牌发现。完整证据 259,462 字节，和用户原报告字节数一致。

## 困难与取舍（面试可讲边界）

问题不是把来源删掉，而是把证据层和决策层分开。同一服务端分析投影支撑看板/报告，诊断是派生视图；有效分母、协议和原文留底。历史 planner 任务存在跨筛选计数、把非提及直接推成官网缺口的风险，本轮采用严格证据范围与保守制作单。任务状态另存，避免“标完成”污染历史测量。这是从数据采集到可解释产品的工程改进，尚不是 GEO 增长闭环。

REA 遇到原生编译重复 module map 与退出清理失败，采用临时 overlay 得到静态证据，并明确不是干净退出。2 个 chunk 静态结果不推断服务端；UI 确认6项建议及 Generate 入口，未核验其内容正确性或真实运营效果。

后续：品牌事实人工确认、去重与跨题内容合并、官网页面审计、事实支持校验、真实发布与固定协议后测；长期里程碑继续维护在原版本队列，不另建路线图。
