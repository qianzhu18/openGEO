## 是什么

OpenGEO 是个人在本机使用的开源 GEO 工作台。用自己的浏览器登录态、API Key 和文件，把 AI 回答变成可回放的证据、可执行的动作、可复测的结论。

成功标准：一个个人用户能从官网得到可回放的报告，并拿它去说明现状。成功不是席位、订阅或“保证被推荐”。

可以沿用的是诊断流程和证据纪律：官网建档、问题、回答原文、引用、动作、复查。云端多租户、账号池、计费和浏览器农场由 Topify 那类云端产品承担，不进本仓库。

## 边界

要做：

- 本地单用户，CLI + 本机网页
- 稳定且允许采集的入口优先网页；不稳定或只有 API 的入口用 API。每条结果标明来源
- 证据留在本机：回答原文和协议；网页另存回答区域 DOM 与截图，API 另存脱敏响应
- 失败显式，未知保持未知，同一输入可以重算

不做：

- 账号、团队、席位、SSO、权限、计费
- 云端多租户、浏览器农场、账号池
- 排名保证、私有搜索量估算、批量内容农场
- 把 API 结果写成网页结果，或把发布写成已被 AI 引用

## 数据分析与报告（2026-11-08 迭代）

本轮优先级按用户最新要求调整为数据分析和调研报告，内容与策略扩展后置。中英文 Overview 和 Sources 共用服务端 `analyzeRun`：运行批次、模型、实际通道、观察日期筛选；有效/计划覆盖、排除/待完成、分组品牌提及、首次出现序、跟踪品牌提及份额、观测日趋势、问题覆盖、域名/URL 信源和原文入口。来源、模型、协议、点名标签、批次、意图分层，混合组不出一个总提及率。没有新采样就没有新增观测，当前趋势只描述选定 run 中的真实日期，不是跨批次增长曲线。

报告与看板使用同一运行快照和筛选；提供 Markdown 与独立 HTML（浏览器可打印为 PDF，服务端 PDF 生成未实现）。默认调研报告不再附策略和内容草稿；JSON 证据导出仍保留既有工作流字段。存在标题污染的历史 run 标记为 QA，不删除原文；失败不进入提及分母。全文指标与失败机制见[采集](采集.md)，交付范围见[案例交付](案例交付.md)。实现证据见[任务记录](OPENGEO-20261108-ANALYTICS-REPORT/Report.md)。

## 现在先做什么

当前先把问题集诊断跑通：按预先冻结的入口采样，同一题在每个入口至多贡献一个有效回答，按网页 / API、平台、模型查看明细和失败原因。这个汇总描述本次选定的入口和问题，不代表市场份额。下一步是把工作台的 Top1 / Top3 汇总与案例枚举名次口径统一，再增加可验收入口和复测频次。指标口径见[案例交付](案例交付.md)。

协作、命令和浏览器硬规则见 [AGENTS.md](../AGENTS.md)。

本地业务流程按「品牌资料与约束 → 问题设计 → 采样与数据诊断 → 策略与内容辅助 → 人工审核发布 → 固定协议复测」迭代。策略与内容当前仍需人工审核；定期调度与真实发布后测未完成。架构评估和可核对的困难记录见[本轮任务](OPENGEO-20261108-ARCHITECTURE-INTERVIEW/Report.md)，工程失败与取舍在对应任务 Report 中持续沉淀。

下一个版本与长期候选已按用户要求整理为 [里程碑复选清单](todo/版本里程碑.md)。这是规划，不是已实现能力或发布日期承诺；Klepsy / Topify 的研究在 [竞品比较](../references/competitors/COMPARISON.md#2026-11-08-国内外商业产品实测)。该轮只做研究与规划；之后的数据分析实现以本页新增说明和对应任务为准。

工程加固：中英文分析运行切换采用请求序号，晚返回的旧选择不覆盖新选择。中文后台轮询受当前运行与选择序号约束；英文选择同步 URL 并重新安排轮询，刷新后仍打开选定运行。

Cloro 接入已由官方 SDK 合约与离线回归验证；实际可用性另按每轮返回记录。远程监测 API 与本机浏览器四件套分开，费用、地区和底层模型未知保持 UNKNOWN。见[采集](采集.md)。


2026-11-08 路由调整：默认国内外均为 API-only；海外 Cloro ChatGPT/Gemini，国内 OpenRouter。中英文 Actions 将 measurement 类任务从品牌建议分离，单列采集状态与运行记录入口；英文证据按钮去重且最多展示 3 条原文和 3 个问题。旧 run 原始观测与动作不改写，切换默认路由不会重采历史批次。


## 0.3.0 本地使用链路

正常路径为「新建/选择独立项目 → 上传品牌来源 → 保存并确认问题 → 选择平台品牌诊断 → 看板/报告/建议」。项目管理支持可恢复删除，隐藏其资料与运行；不是永久擦盘。内置示例默认隐藏，可在项目管理开启。删除不会重启复活，运行中拒绝删除。各项目资料与运行快照独立，切换项目防止旧请求回填。

服务商设置仅 OpenRouter 与 Cloro Key；默认诊断不要求用户手填模型 ID。配置仅在本地服务进程内存生效，重启需重填或由环境提供。平台路由和模型由服务端维护，诊断仍显式确认问题及平台。品牌文件默认上传，支持文字 PDF、UTF-8 TXT/MD；未实现 Word/OCR。实现与验证见[本轮记录](OPENGEO-20261108-PRODUCT-FLOW/Report.md)。

## 0.3.1 诊断空间与执行状态（2026-11-09）

确认问题后创建项目内诊断空间，保存问题版本与原文快照；相同问题重复保存复用原空间，改题建立新空间。平台与选中问题可「保存选择，稍后测试」，不保存凭据。运行通过 spaceId 关联空间，同空间可保留多轮测试。中文工作台 URL 与本机选择偏好恢复空间、运行；历史未关联运行保持原样。空间不等于新账号或团队工作区。英文工作台保留已有项目/运行流程，本轮只共用执行状态展示，独立空间选择尚未接入英文页。

执行状态位于页面最前：按已落盘阶段与已处理单元展示进度，运行中隐藏结果看板、策略/内容和报告导出入口；结束后展示结果，明确区分完成、待处理、失败、中断。100% 代表执行结束，不代表采集全成功；有效覆盖另计。关闭网页不会停止本地进程；服务进程退出后旧运行标为中断，不自动继续请求。当前进度无耗时预测，也不新增自动重试。
