# 实验、指标与公开示例

日期：2026-10-29。E0 已执行；E1 已由本地原型验证其中的业务流程，E2–E3 仍为实验设计。实际运行与验证范围见 [当前原型](04-local-prototype.md)。

## 1. 分开验证三个问题

1. Agent 是否能正确走完业务流程？用合成案例和异常场景检验。
2. 内容组织是否在特定受控条件下影响回答？用固定来源与对照版本检验。
3. 公开网站修改后，真实入口的观察是否变化？用固定问题集和连续线上采样检验。

三项结果分别报告。受控实验无法证明消费级 AI 平台会抓取某个页面；历史数据回放也没有产生新的模型回答。

## 3. E1：合成 B2B 业务闭环

公开示例企业使用全新虚构的“示例传感器厂商”，产品为工业温度传感器。以下数值仅为测试条件：额定产能每月 2,400 件，最近一个月实际出货 900 件。原始资料再加入一份把实际出货误写为产能的摘要，要求系统识别定义冲突。

示例不沿用真实客户的企业名、地区、行业细分、数字组合、客户名单、访谈原话与资质。它保留的是处理冲突、缺失和执行状态的方法。

使用 20 个确认问题：品牌核验 4 个，供应商发现 6 个，产品匹配 4 个，信任核验 3 个，采购决策 3 个。输入回答采用明确标注的合成记录，另用上游公开归档检验格式转换。

完成标准：

| 场景 | 期望行为 |
| --- | --- |
| 产能与出货口径冲突 | 保留来源并发起确认，相关表述在解决前不进入稿件 |
| 没有资质证书 | 标为缺证据，不生成“已认证”结论 |
| 问题候选来自模型 | 标注为推测，不填写虚构搜索量 |
| 问题集修改 | 建立新版本，旧采样保持原版本 |
| 品牌别名命中 | 返回命中的原文；模糊名称进入复核 |
| 品牌被负面评价 | 提及为是，正向推荐为否或待复核 |
| 只有正文 URL | 记录为正文链接，不计入 Provider 引用 |
| 搜索结果未被答案引用 | 记录为检索结果，不计入已引用页面 |
| 请求失败 | 计入计划和失败清单，不当作未提及 |
| 已有原文但分析失败 | 原文保留，判定状态未知，可重做分析 |
| 人工重试成功 | 保留首次失败，不增加独立计划样本 |
| 全部失败或无合格判定 | 显示无数据，不显示 0% 表现 |
| 内容审核通过但未发布 | 状态为待发布，不计入上线数量 |
| 发布后为软 404 或需登录 | 记录正文可见性检查；HTTP 200 本身不代表可用 |
| API 中断或预算状态未知 | 停止新付费调用，已存材料仍可回放 |
| 导出与复盘 | 能从结论返回原文，导出仅含允许公开的字段 |

通过上述 16 项检查，形成一个可演示的闭环；不据此宣称自然推荐率提升。

## 4. E2：受控内容结构对照

要验证的假设：**在事实和候选来源一致时，将企业资料组织成问题导向的内容，是否改善特定模型的事实利用与引用表现？**

实验设置：

- A 版为普通公司介绍，B 版为按同一组事实改写的 FAQ 与参数说明。
- 两版包含完全相同的事实与事实来源，B 不额外增加资质、优势或客户案例。
- 使用隔离的上下文包，版本分别进入新会话；其余候选供应商资料、来源数量和上下文预算相同。
- 来源次序按固定随机种子轮换，并在 A、B 中使用配对的相同次序；检查内容不因截断而丢失事实。
- 20 个开发问题用于调整流程，另外 10 个保留问题在版本冻结后才用于评价。
- 正式比较共 30 个问题 × 2 个内容版本 × 2 个模型配置 × 5 次重复，即 600 个计划回答。模型配置在付费执行前完成预检并冻结；当前没有指定未经预检的模型为可用依赖。
- 回答判定依据原文与预先定义的事实项；人工复核全部冲突项和随机 20% 正常项，隐藏内容版本标签。

主要指标：事实断言正确率、问题覆盖、目标来源引用率、无依据断言数量。提及和正向推荐另列为次要指标。

结果按模型与意图分组。重复回答嵌套在问题下，统计时以问题为聚类单位；报告效应量及不确定区间，不能把 600 个回答当作 600 个独立用户。

若两版在保留问题上没有明确差别，保留“未观察到清晰改善”的结论。该实验仍有价值，因为它能淘汰未经验证的内容模板。

这个实验属于受控上下文研究，只说明被提供的候选材料怎样影响回答。它不证明页面能被公开搜索发现，也不等价于真实 GEO 增长。

## 5. E3：真实公开入口的连续观察

最先使用本项目自身的公开仓库与文档作为对象。这样可以观察真实公开资产，也能将数据与大创客户资料彻底分开。项目尚未公开前，该实验不能开始。

执行协议：

1. 冻结 30 个问题：20 个主要问题和 10 个保留问题；按是否包含品牌分别统计。
2. 选择一个已通过预检、支持搜索证据的 API 配置。协议记录准确模型、端点、路由、语言、地区、会话、参数、实际搜索路径及可用性信息。
3. 在内容变更前的两个独立时点采样；变更后第 7、14、28 天各采样一次。每个问题每轮 3 次新会话，共 30 × 3 × 5 = 450 个计划回答。
4. 干预仅采用一组事先登记的文档调整，例如产品边界说明与同事实 FAQ。保存 Git 提交、页面内容版本、URL、发布时间和访问记录。
5. 选取同类、可访问但未修改的公开项目作为参照对象，在同一批回答中记录其表现，不生成额外暗含推荐的问法。
6. 实际问题文本、模型或入口条件变化时，建立新协议分组；保留原组，避免直接拼接趋势。

主要结果为非品牌问题中的提及、推荐及目标页面引用变化。品牌核验题单独观察事实准确性。样本失败、未知判断和引用能力缺失同时披露。

参照对象用于观察共同波动；单个项目的前后比较仍可能受到时间趋势、索引变化和模型更新影响。只有一个被干预项目时，不将结果写成已证明的普遍因果效果。

网页可访问、被搜索收录、出现在检索结果、被答案引用，是不同事件。没有某个平台的收录验证能力时，记录未知，不由引用缺失反推“未收录”。

## 6. 指标定义

令 planned 为协议预先安排的独立样本数。每个指标只使用具有该指标合格判定的样本作为分母，同时展示该分母占 planned 的覆盖率。

| 指标 | 口径 |
| --- | --- |
| 采集完成率 | 有有效回答原文的计划样本 / planned |
| 分析完成率 | 取得该项可核对判定的样本 / 有回答原文的样本 |
| 品牌提及率 | 原文明确提及已确认品牌实体的样本 / 提及判断合格样本 |
| 正向推荐率 | 原文明确把品牌作为合适候选的样本 / 推荐判断合格样本 |
| 目标页面引用率 | 有可追溯答案引用且 URL 匹配目标页面的样本 / 具备引用观察能力且判断合格的样本 |
| 事实断言正确率 | 与已确认事实一致的可核对断言数 / 全部可核对断言数 |
| 关键事实覆盖率 | 回答正确涉及的目标事实项 / 当前问题预先要求的事实项 |
| 成本与延迟 | 计入全部调用尝试；未知成本单列 |

同一回答可同时为“提及”和“负面评价”。没有涉及某项事实时计为未覆盖，不直接判错；无依据新增的断言另列。

正文链接、Provider 的来源返回、答案与来源的语义支持，分别检查。不同 Provider 的引用语义可能不同，协议标注其证据能力，不能只根据字段名字比较。

首位提及只在回答存在可比较列表且实体对应明确时计算。声量份额若增加，必须另行定义竞争集合与分母；不把提及率换个名字当 SOV。询盘、销售和 ROI 需要额外的客户侧数据，不从提及率换算。

## 7. 费用与失败处理

离线回放默认零模型调用。E2、E3 的数量是完整协议的计划规模，当前尚未执行这些付费测量。

付费运行先用少量样本确认模型、搜索、解析与成本返回是否可用，再冻结预算与运行清单。不能因预算不足而事后挑选成功样本报告；提前终止时保留已执行范围、失败和停止原因。

费用估算使用预检时的当前费率与实测 token，包含搜索、生成、失败和重试。预留单次最大请求费用，并结合 Provider 账户限额；无法确认下一次请求费用时停在预算阻塞状态。

线上效果实验的等待时间与索引行为不可控。项目是否可发布按流程、数据与复验能力验收，效果结果可以为无改善。

## 8. 脱敏与公开材料

公开的内容包括独立编写的工作流、拥有可公开权利的新增代码、合成示例、指标定义、实验协议和明确署名的上游能力。

真实客户文件、访谈录音、联系人、账号、价格、客户关系、内部运营策略和未公开素材继续留在原始位置。本项目文档仅保留方法层面的抽象；替换企业名不足以得到合适的公开示例。

发布前采用字段白名单导出：项目与样本的公开 ID、可公开的问题、原文片段、来源、协议、判定和限制。Token、请求头、私人路径、账号标识及 URL 敏感参数不进入导出包。

只保留可复用的方法规则，例如事实来源、问题版本和分母管理；不把本机路径、商业报价、团队人员分工或特定平台的单次偏好上升为通用 Skill 规则。

第一套公开示例应包含：

1. 合成品牌资料与说明。
2. 事实确认及问题集版本。
3. 明确标记来源类型的回答样本与失败记录。
4. 三个从差距推导出的任务与一份内容草稿。
5. 发布状态演示与两轮对比报告。
6. 结果、限制和可复验步骤。
