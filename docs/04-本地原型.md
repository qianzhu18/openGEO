## 实际运行的案例

三个基础案例执行了同一条本地工作流；另完成了一个新的 API 观察：

| 案例 | 计划记录 | 有原文 | 分析完成 | Provider 引用项 | 正文链接项 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 合成制造业 | 20 | 19 | 18 | 3（合成） | 2（合成） |
| PostHog 历史归档 | 27 | 27 | 24 | 3 | 12 |
| NiubiStar 历史归档 | 3 | 3 | 3 | 0 | 0 |
| PostHog 新 API 观察（未联网） | 2 | 2 | 2 | 0 | 4 |

合成案例故意包含一次采集失败、一次解析失败和一项事实冲突，用来验证行为，不是采集稳定性统计。历史归档的原始时间为 2026-09-08，本次执行的是转换、分析与规划。

流程首先保留冲突并阻塞草稿，选择规格书口径后创建新运行，生成带事实 ID 的选型说明。原先的冲突与阻塞记录继续保留。

## 尚未验证或未实现

- 已验证本机 OpenRouter/Qwen 的两题未联网通路，策略与内容均采用模型输出并通过证据检查；其他 Provider 的实际账号未逐一验证。
- 首次 OpenAI 路由返回地区 403；Qwen 的截断输出与错误事实引用触发了修正。最终结果和所有尝试的状态见 `examples/citekeel-runs/live-summary.json`。
- 问题候选是本地模板和用户输入，没有独立搜索量来源，也未接入自动语义扩词。
- 推荐分析是可复查的邻近措辞规则，需人工核对，不能当作已经校准的语义评估器。
- 监测步骤仅按条件分组，不自动推断趋势、推荐权重或优化提升。
- 发布只登记链接，不执行发布、访问检查或收录确认。
- 尚未执行设计中的 E2 受控内容对照和 E3 线上连续观察。

## 复现方式

在仓库根目录运行 `npm ci`、`npm run demo`、`npm start`，浏览器打开本机 8847 端口。

核心验证为 `npm run check`，浏览器验证为 `npm run test:browser`。后者使用独立测试目录与 8857 端口，不改试用工作台的数据。

`npm run check:upstream` 在 vendor 内安装原有锁定依赖，再执行上游自检；不会改上游源码或发起其付费案例执行命令。

JSON 导出不包含凭据、完整 Provider payload 或模型原始策略回复；原文仍可能包含用户自己录入的信息，导出前应按具体共享目的检查内容。
