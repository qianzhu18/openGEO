# 采集稳定性与名次口径

日期：2026-11-06。问题：个人版怎样稳定拿到 AI 检索回答，并算出「我们输入的问题里，品牌进入前三名的比率」，同时不让 Agent 对着页面一步步判断品牌。

证据分级：DOC 官方文档，JS 以往公开脚本，CODE 本仓库当前实现，DESIGN 本地取舍，UNKNOWN 没有证据。

## 1. Topify 公开说了什么

2026-11-06 重读 [How Topify Works](https://docs.topify.ai/concepts/how-topify-works)。页面仍写明：

- 每个 active prompt 每天送到已配置的 AI 提供方，回答在数小时内收回，再做分析。
- ChatGPT、Perplexity、Google AI Overview、Gemini 通过自动化浏览器会话驱动消费级界面。
- Claude 走 Anthropic 官方 API。
- 每条回答解析四件事：品牌提及、情感、引用来源、竞品信号。原文长期保留，7/14/30/90 天只是查询窗口。

这是 DOC。它说明稳定来自「问题 × 引擎 × 日」的批次和原文留存，没有写浏览器驱动、账号、地区、重试或失败是否进分母。

同日文档索引 [llms.txt](https://docs.topify.ai/llms.txt) 仍把指标定义放在 Brand metrics / Source metrics，把下钻放在 Prompts API。采集工人不在这份索引里。

## 2. 前端逆向到不了采集工人

2026-10-30 至 2026-11-02 已用 [REA](https://github.com/morluto/rea) 分析公开分发的产品脚本，记录在 [Topify 证据包](../../references/competitors/topify/README.md)。那些脚本描述仪表盘、问题表、`avgTop1Rate` 列键和查询接口。

本轮没有再跑一遍 REA。原因是采集会话、队列和重试不在浏览器里发给用户的脚本中；再解析同一类前端包不能把 UNKNOWN 变成事实。已有 REA 结果继续有效的部分是：客户端能证明指标字段和请求存在，不能证明服务端怎么打开 ChatGPT。

因此下面三项保持 UNKNOWN：

- 是否使用某一种用户脚本、Playwright，或自建浏览器农场。
- 同一问题一天内采样几次，失败后是否重试，重试是否进入分母。
- Top 1 Rate 的服务端公式。列配置里见过 `avgTop1Rate`，公开指标页没有给出与 Visibility 不同的定义。

## 3. 个人版不把判断放在直播页面上

Playwright 逐步点击，或让 Agent 反复阅读 DOM 来确认品牌，都不稳定：页面结构一变，判断过程就断。Tampermonkey 仍跑在目标页面里，要么读 DOM，要么挂钩页面自己的响应；它没有去掉「何时算回答结束」，也不能把品牌名次变成可重放的函数。本仓库不新增用户脚本，也不绕过登录、验证码或平台限额。

已经落地的采集是另一层，见 [17 脚本化网页采集](../17-脚本化网页采集.md)：

```text
本机 Xue 上的扩展桥接
  → 提交一次问题
  → 等到完成控件和正文稳定
  → 保存 answer.txt / 回答区域 DOM / 截图
  → 失败样本单独留下，不进入分母
```

ChatGPT 这条链路已有离线测试。真实 Xue 会话、其他平台和每日调度仍未验收。

## 4. 本地 Top 3 率

CODE：`code/src/citekeel/brand-metrics.ts`。

名次是一条合格回答里，已跟踪品牌按首次出现字符位置的排序。Top 3 率的分子是名次为 1、2 或 3 的合格回答数，分母是全部合格回答数。品牌没有出现时不记成第 3 名。采集失败、分析未完成、空回答、别名冲突不进分母。来源、模型、协议或是否品牌词问题不同的样本不合成一个百分比；合并视图分子分母仍保留，比值为 null。

这不是 Topify 的 `avgTop1Rate`，也不是搜索引擎排名。情感分、需求量估算和 CVR 仍然没有可复算公式，字段保持空，不补写。

内容建议仍要挂在这批已保存的问答上：先有合格回答和名次，再按受众与目标决定写什么。没有回答的题目不能用模型补出「前三名率」。
