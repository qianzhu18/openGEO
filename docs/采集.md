# 采集

更新：2026-11-07。官网研究和 AI 回答是两条链路，协议分开保存。

## 官网研究

输入一个公开 URL，在 `code/` 的本地服务里完成：

```text
校验 URL（只允许 http/https，拒绝私网、凭据和非标准协议）
 → 服务端抓取（超时、大小上限、同域重定向）
 → 要求 HTML，再用 cheerio 提取标题、描述和正文
 → 静态页没有可读文本时，无头 Chrome 渲染一次再提取
 → 仍为空则记下失败原因
 → 从来源文本生成主题和候选问题
```

限制写在 `code/src/citekeel/onboarding.ts`：单次研究最多 25 秒、最多 3 个页面；首页失败会试一次 `www` 与裸域互换；跳出提交域名判失败。页面文本是来源证据。没有文本时不根据域名编造简介，没有搜索数据时不写搜索量。

无头渲染只用于公开页的静态 HTML 没有正文。它不登录、不处理验证码、不点击、不滚动。需要这些步骤才能出现的内容，记为没抓到。

界面上会看到的失败原因：

| 原因 | 含义 |
| --- | --- |
| `The URL did not return HTML.` | 返回的不是 HTML |
| `No readable text` | 静态页和渲染后都没有可读文本 |
| `Redirect left the submitted domain` | 跳到了另一个域名 |
| `Research time budget exhausted` | 25 秒预算用尽 |
| `Could not obtain usable public HTML evidence` | 传输失败或被拒绝 |

客户端渲染的空壳页会走这一步渲染回退。以前 `qianzhu.me` 的服务端 HTML 只有空的 `__NEXT_DATA__`，只读静态 HTML 会失败；渲染后才能取出正文。

## AI 回答

当前网页采样只走本机 Kimi 扩展桥接：提交一次问题，等到回答结束，保存完整 JSON 和本地证据。生产路径不使用 Playwright，也不使用旧的专用 profile。`code/src/citekeel/browser/session.ts` 和旧 Playwright engine 只留作历史代码，不能用来采样，也不能用来判断 Xue 是否已登录。

在 `code/` 执行。需要 Node >= 22.13、Chrome 用户 **Xue**、该用户里已连接的 Kimi 扩展和本机 daemon。只连接 loopback。

本机配置不提交，路径是 `data/browser-config.json`：

```json
{"profileName":"Xue"}
```

Chrome 使用非默认数据目录时，可在同一文件写 `chromeUserDataDir`。脚本只从 `Local State` 读取 profile 名称并定位唯一的 Xue，不读 `Cookies` 或 `Preferences`。

```bash
npm run --silent browser:probe
npm run --silent browser:check
npm run --silent browser:ask -- "What is GEO?"
npm run --silent browser:ask -- "你的问题" --timeout-ms 120000
npm run --silent browser:batch -- --file questions.jsonl
```

- `probe`：核验这次连接的是 Xue。不打开 AI 网页，不提交问题。
- `check`：核验 Xue 后，在本任务的空白 ChatGPT 页请求 `/api/auth/session`，只把认证布尔值返回给 Node。身份字段、token 和响应体不输出、不落盘。端点不可用或会话无效则失败。头像和用户名不能证明已登录。
- `ask`：核验、打开空白对话、提交、等待完成、截图前后再核对正文。每次都检查 Xue，失败就停止。
- `browser:login` 不再执行登录。登录和验证码由用户本人处理。`browser:status` 未实现。

Profile 核验使用一次性本机校验 URL，只对 Xue 的 History 数据库做该 URL 的只读查询。不读 Cookie，不扫描其他历史。Chrome 锁住 History 时，把该库和它的 WAL 复制到临时目录，只查这一条 URL，查完即删。隐身、历史关闭，或快照里没有这条 URL，都会核验失败；失败时不提交问题。校验最多等待 20 秒。`chrome://version` 不能当作 profile 核验。

批量文件每行一题：

```jsonl
{"id":"q1","prompt":"What is GEO?"}
```

一轮 1–3 题，题间默认至少 15 秒，最低 10 秒。CLI 和工作台共用本地进程锁。第一题失败就中止，后面的题记 `skipped`。Ctrl+C 停止本地采集；已经提交到平台的问题可能仍在生成，脚本不自动停掉平台生成，也不重新提交。正常中断会释放锁。确认已死的 PID 锁可以回收。

stdout 是 JSON。用 npm `--silent`，避免 banner 混进结果。下面是格式，不是某次真实回答：

```json
{"ok":true,"id":"q1","data":{"engine":"chatgpt","answer":"完整网页回答","citations":[],"url":"https://chatgpt.com/c/…","evidenceId":"…","evidencePath":"…/evidence.json","latencyMs":12345,"protocolId":"browser-ui/v2;…"}}
```

错误退出码 1，中断退出码 130。不自动重试，避免把可能已经提交的问题当成新样本。

成功证据在 `data/evidence/<id>/`：

- `answer.txt`：完整回答。问题在 metadata。
- `page.html`：本次回答区域的 DOM，去掉脚本、表单和无关属性。不保存侧栏和历史会话。
- `screenshot.png`：只截本次回答元素。截图失败不算成功。
- `evidence.json`：UI 来源、桥接方式、profile 核验、认证方式、原问题、引用、时间和路径。模型和地区保持 UNKNOWN。

失败至少留下 `evidence.json`。不伪造空截图，不截登录页和账号信息。未完成的文本写入 `partialAnswer`，有效 `answer` 留空，不进分母。发送时遇到连接错误，用 `submission: attempted` 表示可能已经提交。

发送前会在页面内重新核对用户没有操作、对话为空、输入框是原定问题；只点击一次。完成要求回答与本次问题匹配、停止生成按钮不可见、正文连续读取一致，并有可见的回答复制控件。隐藏或缺失控件保持未完成。引用只取本次回答 DOM 中的可见链接；链接存在不表示支持回答。

用户在采集标签上的键盘、指针、滚轮或粘贴会中止当前批次。脚本看不到其他应用和标签里的输入。每次核验新建专用标签，使用「OpenGEO 采集」标签组；不关闭浏览器、不借用用户已有标签。

工作台的 `channel=browser` 使用同一采集器。Docker 只运行工作台：宿主 worker 通过本机 HTTP 和专用令牌领一批 1–3 题，按原有 Xue 核验与限速执行。容器得到回答、引用和证据 ID，原始 DOM、截图及协议写在宿主机。未启 worker、连接中断、会话未核验时明确失败，不回放成新样本。API 采样单独标注。Perplexity、Gemini 等其他正式网页适配器、自动导入和调度未实现。

平台界面、会话端点和条款会变。遇到验证、登录墙、限额或结构变化就停止。

### 下一轮的入口与补测策略（待实现）

每轮预先冻结「问题版本 × 测量入口 × 时间窗」的计划。网页入口复用已核验的 Xue 与 Kimi 桥接。Playwright 不用于采集，也不作为回退路径。稳定指该入口近期能在同一协议下通过登录、完整回答和证据验收；平台不允许自动采集时，选择人工导入或已配置的 API。

| 测量入口 | 默认路线 | 网页失败时 |
| --- | --- | --- |
| ChatGPT、Perplexity、Gemini | 分别使用允许采集的网页入口 | 有已配置的对应 API 时才补测；保留原网页失败和实际 API 身份 |
| Claude | 独立的 Claude 日常档 API；默认候选为 Sonnet，运行前冻结实际模型 ID | 不占用另外三个入口的名额 |
| DeepSeek、千问、豆包 | 国内网页未达验收时直接走 API，优先固定 Flash 等低延迟档 | 逐平台固定 provider 和模型；Seed Flash 待实测，已试跑的 Seed Lite 可作为单独的候选协议 |

一个计划单元可有多条尝试，但最多采纳一条。网页成功就结束该单元。网页因登录墙、限流、页面结构变动或证据未完成而失败，先落盘失败，按本轮配置决定是否补测。用户主动中止则停止整个任务；发送状态不明时不再自动点击。缺少配置、地区拒绝、拒答、截断、工具调用未结束或无完整证据都显式记录；没有有效回答就保留空缺。诊断尝试与正式面板分开。

新证据格式需允许网页成功、API 成功和失败各自入档。网页记录会话与 Xue 核验、回答原文、回答区域 DOM、截图和协议；API 记录原文、脱敏响应、请求与实际模型、实际服务商、结束原因、请求的搜索设置和响应里可观察的搜索证据。检索结果、正文引用和普通链接各自保存。用独立尝试 ID 追加记录，汇总按计划单元去重，重跑不能覆盖旧回答。

### 工作台历史名次

名次在回答落盘之后计算，实现是 `code/src/citekeel/brand-metrics.ts`。一条合格回答里，已跟踪品牌按首次出现的字符位置排序。Top 3 率的分子是名次为 1、2 或 3 的合格回答数，分母是全部合格回答数。品牌没出现时不记成第 3 名。采集失败、分析未完成、空回答、别名冲突不进分母。来源、模型、协议或问题类型不同的样本不合成一个百分比。

这是工作台历史口径。案例下一轮的推荐名次和全题集汇总见[案例交付](案例交付.md)。Topify 公开文档能说明它按「问题 × 引擎 × 日」留存原文，公开前端能看到 `avgTop1Rate` 这样的列名；采集工人、重试是否进分母、以及该列的服务端公式没有公开证据，保持 UNKNOWN。采集脚本不调用模型判断品牌。没有合格回答的题目，不能补写一个前三名率。

### 验收

离线测试覆盖了 profile URL 核验、正文绑定、完成状态、无效登录、中断、超时、截图缺失、失败排除和进程互斥。测试里的 Playwright 只用于本地 QA。

每次真实采样都重新核验 Xue。Docker 的 `POST /api/browser/check` 验收容器到宿主的连接与 ChatGPT 登录；此检查不发送提示词。适用的消费者网页条款可能限制自动提取；不具备相应许可时使用人工导入或官方 API。
