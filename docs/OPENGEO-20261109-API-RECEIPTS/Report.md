## 根因与变更（JS）

原 `ModelSession` 只有在 `provider.run()` 成功返回后才保存响应；上游适配器遇到 HTTP 错误或空回答会先抛错，导致已返回的 request/generation ID、费用、用量和错误正文丢失。Cloro 也在 HTTP 失败时丢弃正文。截断保留了部分回答，却没有停止后续付费题；本地停止还容易被误认为网络调用。

新增请求级 AsyncLocalStorage HTTP observer：调用前记录发送尝试，读取响应后先脱敏、保存、等待落盘，再让适配器验证。传输状态与调用状态分别保存，未真正进入发送路径的题标 `not_started`；超时只有 `attempted`，不假定免费。非 JSON 错误正文保留在 `unparsedBody`。凭据值及常见凭据字段递归脱敏，HTTP observer 不记录请求头。

ModelSession 与 Cloro 采样关联 `sampleId/queryId/unitId`。错误后样本仍能取回已留存的响应和文本；完整且未提及品牌的回答继续有效。截断、已知拒答/过滤、未完成工具调用和既有规则识别的登录/限流文本排除分析并停止同目标后续请求。独立目标仍可继续。分析未完成使运行进入 `needs_review`。本轮未改品牌 Top1/Top3 公式；工作台仍是已跟踪品牌的首次出现序，不能当作全候选推荐名次。

简报 / HTML 显示对账摘要，完整证据追加逐笔调用表，JSON 新增 `apiReceipts`。摘要只统计本轮 measurement，费用不跟随品牌分析筛选变化。策略/内容调用可以留存原始回执，但不进入这一采样金额；独立官网模型研究不在本轮回执范围。已报告费用小计可展示历史值，但历史发送与回答关联未知，不补认请求数、成功率或完整总费用。
