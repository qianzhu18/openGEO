# 脚本化网页采集

更新：2026-11-06。

## 目标与调研边界

把逐步远控改为 `CLI → 本机浏览器桥接 → 提交问题 → 等待完整回答 → JSON + 本地证据`。消费级网页仍然需要浏览器运行；脚本不依赖 Playwright、远程浏览器服务或 Agent 每一步判断。

调研记录：

- **JS**：2026-11-06 在 Xue 的空白 ChatGPT 页看到输入框是 `div.ProseMirror[contenteditable="true"][role="textbox"]`，没有 `#prompt-textarea`。问题由页面脚本 `insertText` 写入；写完后发送按钮的 `aria-label` 为「发送」。旧的 textarea 选择器只保留为回退。这次只确认了输入框和发送按钮的结构，还没有把一题提交出去。
- **NET**：本机 Kimi WebBridge 可响应 `navigate`、`evaluate` 和 `cdp`；`chrome://version` 不允许 DOM 读取，不能用它冒充 profile 核验。
- **UI**：本轮桥接创建的任务标签在「用户1」窗口，未证明连接 Xue。因此没有提交真实问题，也没有采集真实回答。
- **设计**：profile 核验采用一次性本机校验 URL，只对 Xue 的 History 数据库执行该精确 URL 的只读查询；不读取 Cookie，不扫描其他历史。Chrome 锁住 History 时，把该库和它的 WAL 复制到临时目录，只查这一条 URL，查完即删。隐身、历史禁用或快照里没有这条 URL 时核验失败；失败不提交问题。校验最多等待 20 秒。
- **待验收**：Xue 桥接下的身份端点、输入、流式结束、正文 DOM 与截图。离线 fixture 通过不等于真实平台通过。

## 已实现的脚本入口

在 `code/` 下执行。需要 Node >=22.13、Chrome 中的 Xue、已在该用户连接的 Kimi 扩展及其本机 daemon。只连接 loopback 地址，不接远程服务。

本机配置已被忽略提交：`data/browser-config.json`：

```json
{"profileName":"Xue"}
```

Chrome 使用非默认数据目录时，可在同一配置中额外填写 `chromeUserDataDir`。脚本只从 `Local State` 读取 profile 名称映射，定位唯一的 Xue，不读取 `Cookies` 或 `Preferences`。

```bash
npm run --silent browser:probe
npm run --silent browser:check
npm run --silent browser:ask -- "What is GEO?"
npm run --silent browser:ask -- "你的问题" --timeout-ms 120000
npm run --silent browser:ask -- "你的问题" --daemon-url http://127.0.0.1:10086
```

- `probe`：核验实际连接 Xue，不访问 AI 网页、不发问题。
- `check`：核验 Xue，再在本任务空白 ChatGPT 页请求 `/api/auth/session`；只将认证布尔值返回 Node，身份字段、token 和响应体不输出、不落盘。端点不可用／会话无效时失败，不以头像或用户名证明登录。
- `ask`：核验 → 空白对话 → 提交问题 → 等待完成控件与文本稳定 → 截图前后再核对正文 → 返回完整 JSON。每次都检查 Xue，不回退。
- `--help` / `-h`：所有命令均可查看帮助，无需连接浏览器。
- 旧 `browser:login` 不再执行登录；登录／验证码由用户本人处理，`browser:status` 未实现。

批量输入 `questions.jsonl`，每行一题：

```jsonl
{"id":"q1","prompt":"What is GEO?"}
{"id":"q2","prompt":"How should a small company measure AI visibility?"}
```

```bash
npm run --silent browser:batch -- --file questions.jsonl > results.jsonl
```

一轮 1–3 题，默认题间至少 15 秒，最低 10 秒。CLI 与工作台共用本地进程锁，不能同时驱动采集。第一题失败便中止批次，后续题输出 `skipped`，不会重发。Ctrl+C 停止本地采集；已经提交给平台的问题可能仍在生成，不自动停止平台生成或重新提交。强制杀死进程不保证写完失败记录，正常中断会释放锁；确认死亡的 PID 锁可自动回收，不会抢占活跃进程。

输出 stdout 为 JSON，使用 npm 的 `--silent` 避免 npm banner 混入；Node 的 SQLite 提示在 stderr，不是结果数据：

```json
{"ok":true,"id":"q1","data":{"engine":"chatgpt","answer":"完整网页回答","citations":[],"url":"https://chatgpt.com/c/…","evidenceId":"…","evidencePath":"…/evidence.json","latencyMs":12345,"protocolId":"browser-ui/v2;…"}}
{"ok":false,"id":"q2","error":{"code":"answer_timeout","message":"未确认回答完整结束…","evidencePath":"…/evidence.json"}}
```

以上为格式示意，**不是本轮真实回答或耗时**。错误退出码为 1，中断为 130；不自动重试，避免把一次可能已经提交的问题当作新样本重发。

## 证据与边界

成功证据在 `data/evidence/<id>/`：

- `answer.txt`：本次完整回答；问题保存在 metadata 中。
- `page.html`：本次回答区域的 DOM，经去脚本、表单和无关属性处理；不保存侧栏或历史会话。
- `screenshot.png`：只截本次回答元素，避免账号菜单／侧栏；截图失败不算成功。
- `evidence.json`：UI 来源、桥接方式、profile 核验方法、认证方式、原问题、引用、时间和文件路径。模型与地区仍为 UNKNOWN。

失败至少保留 `evidence.json`，可能有失败前已保存的文件；不为凑齐三件套伪造空截图，不截图登录页或账号信息。部分生成文本写入 `partialAnswer`，有效 `answer` 保持空，不进入分母。发送命令遇到连接错误时用 `submission: attempted` 表示可能已经提交，不错误声称“未提交”。

完成判定要求回答与原问题匹配，停止生成按钮不可见，正文连续两次读取一致。可见的复制按钮必须位于本次回答之后、用户消息之外；隐藏按钮不算。页面上完全没有复制控件时，停止按钮消失且正文稳定即可。只看“文字几秒没变化”不算完成。引用仅限本次回答 DOM 中能读到的链接，不承诺提取平台全部隐含引用；链接存在不证明来源支持结论。

真实用户对采集标签的键盘／指针／滚轮／粘贴操作会中止当前批次，下一题导航前也检查接管标记。脚本无法监测其他应用或所有 Chrome 标签中的输入，不能声称提供全局用户活动检测。任务页归入「OpenGEO 采集」，固定 session 为 `opengeo-collector`，只复用本任务标签，不借用用户其他标签。不会自动关闭浏览器或现有标签。

工作台的 `channel=browser` 复用此 collector。API 采样路径继续单独标注。Perplexity、Gemini、国内平台在这条脚本链路中**未实现**，不回退到旧 Playwright profile；Campaign 自动转换／导入采集结果和定时 scheduler 也**未实现**。

消费级平台 UI、会话端点与策略会变化，自动化存在平台条款与账号限制风险。遇到验证、登录墙、限额、结构变化就停止，不提供绕过功能。

品牌验证发生在回答落盘之后。`brand-metrics.ts` 读取 `answer.txt` 对应的文本，按已跟踪品牌的首次出现顺序给出名次；Top 3 率是名次为 1、2 或 3 的合格回答数除以全部合格回答数。采集脚本不调用模型判断品牌，也不把未出现写成第 3 名。用户脚本管理器不能替代这次“保存一次、离线重算”。

## 当前验收

- 离线 fixture 验证 profile 精确 URL 核验、正文绑定、完成状态、无效登录、中断、超时、截图缺失、失败排除和进程互斥。测试使用 Playwright 作为本地 QA 工具，生产脚本不依赖它。
- 2026-11-06 的 `browser:probe` 返回 Xue / Profile 11，方法是 `exact-task-history-url`。同一窗口的 ChatGPT 会话端点返回已登录。注入使用 ProseMirror `insertText`，提交使用带焦点模拟的 `mouse_click`，点击后保留约 1 秒再取消焦点模拟。
- 同一天的真实 `ask` 能提交问题并读到正文，但完成判定曾经把旁边的「复制」按钮漏掉，整段回答被记成 `answer_timeout`。判定已按该页结构调整。自动记为 completed 的端到端仍要以修复后的一次 `ask` 为准。
- 未完成六平台基线、连续三天调度和效果复测，不将离线通过写成采集成功。
