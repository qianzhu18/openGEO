# 报告：OPENGEO-20261108-V5-QUESTION-VALIDATION

## 结果

问题集解析现在会剔除中英文展示标题，例如 `非点名题`、`点名题`、`**非点名题**` 和 `## Unbranded questions`。只包含标题的题集会被拒绝；空行和仅大小写不同的重复项会被移除；编号问题的原文和顺序保持不变。

修复覆盖以下入口：

- 保存工作台问题集；
- 非诊断真实运行前确认问题；
- 新增或编辑 Prompt。

这能防止粘贴进来的报告分组标签变成测量单元。

## 工程审计

### 1. 是否完成优化

已完成。修复不是手工剔除某一次粘贴结果，而是新增可复用的解析器 `code/src/citekeel/question-set.ts`，并让所有相关问题入口统一使用。

### 2. 是否造成 Breaking Change

没有公开 API 契约被删除或改变。

以下非目标输入会被拒绝或丢弃：

- Markdown 章节标题被当作 prompt；
- 只包含展示标题的问题集；
- 仅大小写不同的重复问题；
- 超长或超出数量限制的问题集。

正常编号问题、普通点名题和非点名题仍然会被接受。既有持久化项目无需迁移；环境变量、命令、路由、Schema 字段和存储格式都没有删除。

后续显式问题分类涉及 Schema 演进，刻意延后并列在 `Todo.md`。

### 3. 英文注释

新增导出的解析器带有专业英文 JSDoc，说明为什么要丢弃展示标题。没有添加无关行内注释。

### 4. 单元测试

测试位于 `code/test/question-set.test.ts`，覆盖：

- 中英文分组标题剔除；
- Markdown 标题和普通标题剔除；
- 编号问题文本与顺序保留；
- 空行和仅大小写不同的重复项剔除；
- 仅标题题集拒绝；
- 数量和长度限制。

### 5. 测试位置

本仓库是 TypeScript，不是 Rust，因此不适用 `#[cfg(test)]`。所有新增测试都放在独立的 `code/test/` 目录，没有混入运行时逻辑，符合仓库惯例和用户要求。

## 验证

在 `code/` 执行：

```bash
npx tsx --test test/question-set.test.ts
npm test
npm run build
```

定向测试 7 项通过；完整测试 97 项通过、0 项失败；TypeScript 构建通过。

## 剩余风险

解析器能防止标题污染，但尚未建模问题意图和候选列表。例如，同时显式点名 PiPER 和竞品的问题，不应与完全自然发现的问题混在一个分母里。这需要显式问题分类字段，应作为独立、可评审的变更处理。
