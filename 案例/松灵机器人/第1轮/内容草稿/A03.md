# Choosing a ROS teaching robot: navigation platform or mobile manipulator?

> Independent editorial draft based on public sources. Prepared for review; not issued or approved by AgileX Robotics. Product statements are attributed to their sources and have not been independently tested.

## Choose the learning outcome first

Start with the experiment students must complete. A navigation course may assess mapping, localization and path execution. A mobile manipulation course adds a task involving an arm and an object. These are different teaching objectives, even when both use a mobile base.

Write the required demonstration and its observable result before selecting hardware. This keeps a platform with appealing features from setting the syllabus by accident.



## Read the exact configuration, not only the family name

AgileX presents LIMO PRO for mobile-robot learning and development. Its FAQ says the standard configuration does not include an arm and distinguishes it from LIMO COBOT. Confirm the actual configuration on the quotation rather than assuming every product in the family includes manipulation hardware.

A course comparing mobility configurations and a course assessing grasping need different equipment and evidence. Ask which configuration is being supplied and what additional integration remains.

Source: [LIMO PRO 产品与 FAQ](https://global.agilex.ai/products/limo-pro)。

## Make the software environment part of the course specification

The captured LIMO ROS 2 repository uses a Humble branch, and its README identifies an Ubuntu environment. Treat that as a specific documentation path, not evidence of support for every distribution.

The course handout should record the operating system, ROS distribution, package revision and hardware configuration together. Before students use the platform, an instructor should reproduce the lesson in that same environment and preserve the result. This independent draft has not executed the repository.

Source: [LIMO ROS2 Humble 说明](https://raw.githubusercontent.com/agilexrobotics/limo_ros2/humble/Readme.md)。

## Separate the first experiment from later extensions

For the first experiment, choose one task with clear inputs and observations. Explain which data should appear, what the student should record and how the instructor will evaluate the result. Add later extensions only after the baseline is reproducible.

A teaching record should include the initial conditions, software version, observations and failure symptoms. A video of a successful run can illustrate the lesson, but it does not replace a lab procedure.



## What should the supplier and instructor confirm?

Confirm the supplied hardware, relevant documentation, development environment and support route. Then align the lesson with the students’ experience and the lab equipment already available.

If a public parameter label is ambiguous, request clarification before using it in the procurement table. Keep the confirmed definition, units, configuration and source date with the final teaching materials. No payload, price or performance assumption is required to make this selection process useful.
